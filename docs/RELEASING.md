# Releasing KaggleFleet

Releases are automated from `main`. After a PR updates `__version__` and `CHANGELOG.md`,
[`.github/workflows/auto-release.yml`](../.github/workflows/auto-release.yml) creates
`vX.Y.Z` when that tag does not already exist. The tag then starts
[`.github/workflows/release.yml`](../.github/workflows/release.yml), which verifies that the
commit is on `main`, builds the sdist and wheel, publishes them to PyPI, and creates a
GitHub release with notes from `CHANGELOG.md`.

## One-time setup

1. **PyPI Trusted Publisher.** Sign in at https://pypi.org, open
   *Your account → Publishing → Add a new pending publisher*, and enter:

   | Field | Value |
   |---|---|
   | PyPI project name | `kaggle-fleet` |
   | Owner | `towhaEL` |
   | Repository name | `KaggleFleet` |
   | Workflow name | `release.yml` |
   | Environment name | `pypi` |

   After the first successful release the publisher becomes a normal one, and no API token is
   ever stored in GitHub.

2. **GitHub environment.** In the repository, open *Settings → Environments → New environment*
   and name it `pypi`. Adding yourself as a *required reviewer* is recommended, so every
   publish waits for a click.

## Cutting a release

1. Update `__version__` in `src/kaggle_fleet/__init__.py` (Semantic Versioning).
2. In `CHANGELOG.md`, move the `[Unreleased]` entries under a new `## [X.Y.Z] - YYYY-MM-DD` heading.
3. Commit and open a PR targeting `main`:

   ```bash
   git commit -am "Release vX.Y.Z"
   git switch -c release/vX.Y.Z
   git commit -am "Release vX.Y.Z"
   git push -u origin release/vX.Y.Z
   ```

4. Merge the PR. The *Auto Release* workflow creates the tag automatically, and the
   *Release* workflow publishes it. The build fails early if the tag and
   `__version__` disagree or the changelog has no section for the version.

## Checking a build locally

```bash
pip install build twine
python -m build
twine check --strict dist/*
pipx install --force dist/kaggle_fleet-*.whl && kfleet --version
```

## README images

`docs/images/banner.png`, `social-preview.png` and `demo.gif` are generated by
`scripts/media/build.sh`. The demo runs the real `kfleet` CLI against a fake `kaggle`
executable (`scripts/media/fake_kaggle.py`), so it needs no network or Kaggle account.
Images in `README.md` use absolute `raw.githubusercontent.com` URLs so that they also render on PyPI.
